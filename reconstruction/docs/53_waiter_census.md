## 2. 两个新宿主能力（保留资产）
- `H_IRQTICK`：I_STAT(0x1F801070) 每次读自增 → 打破 32 次定长轮询；`H_STATMASK` 变体按位注入。
- `FWDSERVE`：嵌套根call服务端——host 影子栈(512×64)全量上下文切换，**尾跳重放语义**
  （父在向量入口的 pc+t1/t2 恢复即重新派发；v0 逐层上传）。实证嵌套链最深 400+ 层。

## 3. 定性反转（本档核心结论）
IRQ 族逐项独跑 blocks 205→**4157**、haltpc 从 `0x0` 质变为 `0xB0` 深链——服务体本身**完全可执行**，
收敛形态是**永不返回的尾跳链 = 事件等待循环**。`0x3d` 自递归族（ROM+0x406c 自 jal + rootcall 自嵌套，
入口 `addiu sp,-24; sw a0,0x18(sp); ... jal self`）为 printf 型字符打印服务。
**ctx24 不是"数据语境洞"（补数据可救），而是 WAITER 语义（必须事件生产者+线程调度器喂）——
docs/44/45 的"设备事件生产者"墙在 per-service 粒度独立复现。**
`H_GP=10`（0x3d 的 r28==10 门）与 `H_STATMASK=0xFFFF` 组合不改变终态（恒定 ok=2 ctx=22 全序）。

## 4. 非 waiter 候选（唯二走得深的）
- `b0/19`：118,051 块，haltpc=`0x80058628`（C2 RAM 深码）——最深可行成员，优先做批3楔子2。
- `b0/15`：haltpc=`0xa000e028`（引擎堆码/对象 vtable 跳）——真引擎对象依赖。
- `b0/4a`：全序中 `rc=0`（序依赖转化，呼应 docs/51 批次态依赖）。

## 5. H-25 批3 更新
转化数在当前宿主 = 0/24（等待语义，非缺数据）→ 批3 第一步从"对象建模"精确化为
**事件生产者 + 定序调度器**（谁在等哪个事件位/消息，喂了才醒）；输入件 = 本档 §1 分族 +
FWDSERVE/H_IRQTICK 能力 + 0x19/0x15 两个非 waiter 探针点。
