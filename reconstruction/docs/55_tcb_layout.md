# 55 — M-12 批3楔子3：调度器语境完全画像与槽注入否证（task-069，SESSION-78）

## 1. `0x80058628` 函数全量语义（= suspend-current-thread，字段清单）
```
lw  a1,[0x80089C44]      ; 当前线程 TCB 指针
t6=[a1+4]; bit3=ready    ; 未 ready → v0=0 直返
lw  v0,[a1+0]            ; 当前线程栈指针字段
[a1+0] = 0xFFF7          ; suspend 标记
v1=[0x80089C3C]          ; 备用栈对象
[v1+0] = ([v1+0]&0xFFFF) | 0x88000000   ; ★ sp 高16位=0x8800 uncached 别名段
jal ROM+0x6AB90(a0=当前栈,a1=0x10)      ; 保存帧
```
伴生槽 `[0x9C28]/[0x9C30]/[0x9C34]` = 字节态（lbu），伴生函数 0x58720 族读之。

## 2. ready 队列实物（golden RAM[0x6CE0]，sp/ra 平行数组布局）
```
0x6CE0: [0x66C4, 0x67B8, 0x6870, 0x6928, 0x85D8 | 0xF40, 0x85D4 | 0...]
         线程栈指针×4 + 被切换线程栈 0x85D8      saved-ra 表(RAM[0x85D4]=0xE10)
```
0x19 的 118k-blocks 运行正是消费这张**尸检语境表**：恢复 sp=0x85D8 → `jr ra(0xE10)` →
C2 thunk 池（RAM[0xE00] 族）→ EMITFAIL pc=0x26F0 数据页。phys() 回绕语义已核
（A20-A0 解码，0x880085D8→RAM 0x85D8 与真机一致——**非 JIT 缺陷**）。

## 3. 槽注入实验与归因
`FWDTcb`（[0x9C44]/[0x9C3C]→构造 TCB，flags=0x8）后 0x19 **118,051 blocks 逐字节不变**。
诚实注明：0x58628 在 fwd 语义里是**返回目的地**（halt 于其取指边界，函数体未执行），
单槽注入不构成消费点判据。主证为**数据吻合**：切换后的 sp=`0x85D8`/ra=`0xE10` 恰等于
ready 队列 `0x6CF0` 槽与其 saved-ra 表项（golden 全 RAM 中 `0x85D8` 值唯一出现位点），
即消费的是**队列整体（≥5 sp 槽 + saved-ra 表 + 每线程 0x66C4 型帧上下文）**，非单槽。
→ 三件套不是"填表"，必须**运行期构建**：真实调用建线程 → 队列自然生成 → 事件唤醒。

## 4. 顺带修正与能力
- SENT 窗判定收紧（task-068 遗留风险）：深层 `jal 0x80058628` 的返回点恰落 SENT 窗，
  宿主现要求 `ra≥0x80000000 && nst==0` 才认顶层完成——防 rc=0 假阳性。
- 新保留能力：`FWDTcb`（TCB 槽注入，供未来调度器实现回归）、`FWDTcbKeep`（只建 tcb 不压槽）。
