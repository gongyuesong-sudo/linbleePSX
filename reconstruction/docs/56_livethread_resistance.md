# 56 — M-13 批3实现1：填表式活线程的三层阻力画像（task-070，SESSION-79）

## 0. 本楔问题
"能否用纯填表（静态注入队列/槽/帧）把 0x19 调度器喂成可完成切换？" —— 答案：**不能**，
且阻力精确分层如下（全部实测锚定，host60 复算）。

## 1. 三层证据（毒值法 + 切换时刻语境快照 QDUMP）
1. **sp 层 = 表驱动（可填）**：队列 `[0x6CE0..0x6CF4]` 五 sp 槽写毒值 `0xDEAD0000` 后，
   切换时刻 `sp=0xdead0000` **完全跟随**——消费点确为该表，注入不被回写（QDUMP q0/q4 切换时仍毒值）。
2. **ra 层 = 非内存来源（填不动）**：`ra=0xE10` 钉死。切换时刻全 RAM 中值 `0xE10` 的唯一槽
   `RAM[0x85D4]` 已被注入为 `0xBFC4C1B0`（QDUMP m85d4 证实未被覆盖），ra 仍 `0xE10`
   → ra 恢复自**寄存器级在飞语境**（JIT 代码缓存 block 内联/在飞寄存器），非任何可静态写的槽。
3. **tcb 层 = 运行期覆写（填了也白填）**：注入 `[0x9000]` TCB sp 字段 = `0x88000000|spn`，
   切换时被 suspend 语义回写为旧线程真值 `0x880085D8`（QDUMP tcb0）——TCB 是运行期活结构。

## 2. 建线程前置序列实验
`docs/41` 最小集先跑（00,01,07,08,0c,12,1c → 19）：0x00 在 115,871 块后 halt `0x40E4`（低页），
其后全部 ctx=200 拖死——**创建服务自身也需要事件语境**，序列法不通。

## 3. 终判（H-25 批3实现规格定稿）
纯表填/序列预跑均不可行。三件套必须**事件驱动运行期实现**，最小闭环 =
1. 真 `NewThread` rootcall 走通（需 0x19 族的等待可被满足 → 依赖 2）；
2. **事件生产者**：vblank/CD 事件位按节拍喂 I_STAT + `0x3d` 字符输出消费者（TTY 收字不再自嵌套）；
3. **切换完成语义**：ra 在飞语境由**宿主 JIT 提供线程恢复出口**（在 `lw sp,[queue]` 后注入
   `ra=线程入口` 的宿主钩）或实现 ROM+0x6AB90 帧保存/恢复对（`mips_dis` 可继续挖）。
实施顺序建议 2→1→3（事件生产者最独立，可先行；hprobe 的 CD 族 serve=51 群即其验收面）。

## 4. 保留能力
`FWDLiveThread`（队列+TCB+ra 槽三点注入）、`FWDPoison`（毒值切换追踪）、`QDUMP`（切换时刻语境快照，
FWDLiveThread 下自动）。
