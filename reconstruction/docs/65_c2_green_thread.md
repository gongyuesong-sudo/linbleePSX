# 65 — 出口A第一刀：magic 无中生有否证 + C2 绿色线程模型发现（task-080，SESSION-89）

## 1. Magic `0x27D54445` 出处扫描：全源 0 命中（否证）
金标准 RAM 2MB / BIOS SCPH1001 / 三流（含 relocated）全扫描：**0 处**。
定性修正：该值属 htrace 时代**已弃用的宿主 stub 参数**（仅存在于被压缩的会话记忆），
guest 宇宙中从来不存在。"反推 NewThread 参数块"的任务前提被本扫描直接拆除。

## 2. 重大发现：所谓"线程"是 C2 私有绿色线程（协程），BIOS 线程 API 零参与
金标准实证（docs/55 五栈队列的运行时真相）：
- **双份工作区**：`0x66C4..` 帧（96B）与 `0x42D24..` **逐词全等**（delta `0x3C660`）；
  该帧**不在静态流镜像内**（relocated stream find=-1）→ 运行时堆分配+复制的工作区。
- **栈顶水位哨兵 `0x93A20020`** 共 10 处：`0x66C4/67B8/6870/6928/69E0` + `0x42D24/42E18/42ED0/42F88/43040`
  —— 两套五栈镜像（运行/主副本），间距一致。
- **帧内容 = C2 私有字节码指令流**：模式词 `0x2C41xxxx` / `0x14200005` / `0x10200004` / `0x100000xx`
  （非 MIPS 指令——这是 C2 自研 VM 的代码/数据混合帧）。
- 就绪队列 `RAM[0x6CE0]` = `[66C4,67B8,6870,6928,85D8, F40,85D4]` 复Dump 确认。
- 五栈 sp 在全 2MB **无任何指针引用**（队列除外）→ 调度纯表驱动，无 TCB 链。

## 3. 勘正与推论（修正 docs/54/55/56 措辞）
"TCB/线程调度器/NewThread"应读作 **C2 引擎内建协程调度**：docs/54 的 `0x80058628`
读 `[0x80089C44]` bit3 = C2 协程状态词；docs/56"三层阻力"= 工作区+调度表+VM 语境一致性。
**推论（本刀核心价值）**：BIOS 兼容层/真 NewThread 路线**结构性无法到达**该缺口——
要过的不是 BIOS 服务，是 C2 私有 VM。剩余缺口重定义=**C2 绿色线程 VM 语义实装**
（`0x2C41/0x1420/0x1020` 族字节码解码 + 调度循环），属独立大型工程。
