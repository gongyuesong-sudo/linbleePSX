## 2. 真相：三块僵尸三角环（census 实据）
100M 块 SEQTOP：**`pc=0x0000 ×33,333,318 + 0x0080 ×33,333,317 + 0x0100 ×33,333,317`**（三角整环）。
`H_SVCW` 现场恒定：`ra=00000000 sp=800dfee0 t9=80079d00`。
机制链：`0x80`(RAM 向量页 lui k0 序列) → 处理路径跳 `0x100`(SVCLOW thunk) →
`jr ra` 而 **ra=0**（调用链早已断裂，非 jal 保存值）→ `0x00`(nop sled 线性滑行) → 回 `0x80`。

## 3. 对楔2"亿块跑穿"的诚实重估（重要）
100M 跑穿是**真的执行**（无死跳、指令流合法），但内容 = 默认核 thunk 造成的
僵尸三角——**推进指标虚高**。楔1 的 `jr t9(0xFFFF)→0x10C` 死亡本質 =
BIOS 码段(`ra=8005a314`，0x5A314 处数据形态存疑)发出的低页调用；SVCLOW 把它
从"死"变成"僵尸循环"——这是本战役第一个需要**反指标防腐蚀**的教训入账：
主运行真实进度 = 首个带语义的服务完成数，而非块数。
