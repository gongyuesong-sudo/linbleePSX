# 67 — A3 立项楔1：主运行 harness 与 0x10C 宿主服务槽墙（task-083，SESSION-92）

## 1. A3 正式立项与楔1资产
用户第 27 次"继续"= 批准终封公布的默认续行 **A3 完整 C2 执行环境**。
新能力 `FWDMAIN=<budget>` + `FWDRCLOG=<file>`（tools/fwd_test.c）：fwd 语境
（真机金标 RAM + ROM + JIT）直入 C2 主入口 `0x400004` 长预算主运行，rootcall 全记账。

## 2. 首跑 census（实测）
M0 基线与 M1 六件套全开，20M 预算：
```
MAINRUN rc=114/121 kind=2 endpc=000000b0
EMITFAIL pc=0000010c op=0x00000004 ra=8005a314 sp=800dfe90 v0=1 t9=0000ffff/0
PREV[..]=0e10 0e28 0e38 0e44 8005a1d8 8005a1e0 8005a308 8005aba0
```
- C2 kernel 自 0x400004 起步，经 8 词 thunk 序列走到 `8005aba0→8005a314`，
  `jr t9` 目标 `0x10C` 数据值 `4` → 死跳低页。
- **六件套对本停滞零增益**（符合预期，见 §3）。

## 3. 定性：0x10C = 宿主服务指针槽（docs/61 劫持点的主运行形态）
- `op=4 = jr t9`，`t9=0xFFFF/0x00000000` = 未注册服务号——C2 引擎在启动极早期
  就调**宿主服务接口**（与 0x3d 打印服务不同层，是引擎级 ABI）。
- 同一槽位在 htrace 路线的解法已是金标准：`cb[0x68/4]=host_service_cb`
  （htrace.c L339，宿主回调表安装）——金标 RAM 里该槽存的是**真机宿主**的值，
  在本宿主上解引用即数据 `4`。
- 因此主运行的第一墙**不是 C2 内部问题，是宿主 ABI 桥缺失**：
  需要给 fwd 语境装一张"宿主服务回调表"，把 guest 的引擎级调用转发回宿主实现。

## 4. 楔2 定靶（下一砖）
从 `ra=8005a314`/thunk 池反推 C2 期望的宿主服务向量语义（调用约定同 htrace
host_service_cb 那一族），在 fwd 内实现 **MainRun 宿主桥**（表槽→宿主 C 函数，
打印/内存/初始化类先通），复测推进 census。此桥是 A3 的第一块真路基——
本楔验收=停滞点钉死+机制定性+路线打通（htrace 已证同类桥可行）。

## 5. 路线意义
主运行 harness 建成后，H-27 六件套（此前只在孤跑服务语境验证）首次与
C2 主循环同场；届时"六件套是否推进主运行"才成为可测命题。
