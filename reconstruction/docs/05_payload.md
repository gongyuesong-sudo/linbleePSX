# 05 · 追加 payload: 已知 / 未知 边界

## 已知 [观察]

- 范围: 文件偏移 `0xFA00 .. 0x55DF4`, 共 287,732 B (占文件 82%)。
- 结构: 前段高熵 (整体 7.317 bit/B); 尾部 `0x42A00..EOF` 为低熵明文代码岛
  (4KB 块熵 <6.8), 其中 `0x55338..EOF` (2,748B) 已被 Ghidra 完整反编译
  (docs/03)。
- 入口协议: 引导器 `CALL view+0x55338 (EAX=view)`; 桩再 `CALL view+0xFA60`
  —— 0xFA60 在加密区, 只能由桩解压后才存在。
- 载荷组织: 5 个模块 + 块链表, 16B 描述符 + "RAND" XOR 校验 (docs/03 §3)。
- 行为学侧写 (来自明文错误表/导入/对话框, 推断): 限时试用、调试器检测
  (错误 5/6)、CD 在位检查 (dlg 30008)、EULA 门 (dlg 30004)、
  注册表配置读写 (ADVAPI32 7 件套)、DirectDraw 显示 (USER32/GDI32 面)。

## 未知 [静态不可达]

1. 压缩令牌树的精确嵌套顺序 (lzss.c 标注了逐支置信度)。
2. API 编号表 0x10000.. 的完整映射与真实函数指针来源 (运行期构造)。
3. 块描述符表在视图内的基址 (g_desc_table_rva) 与各头字段常量。
4. 引擎本体全部代码: dyna-rec 模拟器核心、光驱时序仿真、限时逻辑、
   反调试实现 —— 需先解密。
5. 是否存在第二层加密 (桩内未见第二密钥痕迹, 但不能排除)。

## 推进路线 (若未来要恢复 payload 本体)

静态已到边界。下一步只能**受控动态**: 在隔离 Win9x/wine 沙箱里运行原
EXE, 于 `CALL view+0xFA60` 前后 dump 解密区, 再喂回 REA 做整区反编译,
回填上面 [未知] 项。该操作会执行原始第三方代码, 需要用户明确授权后另开
任务, 不属于本次交付。
