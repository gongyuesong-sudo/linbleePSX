# 83 — x86 战线楔8：三判据连续否证——静态路线封顶，主循环归动态战役（task-100，SESSION-109）

## 1. 判据尝试与否定链（全部可复算）
| 判据 | 结果 |
|---|---|
| 大循环(>0x100,call≥20)×状态块 disp≥4 | **≈180 候选/22 disp(181 全量集; 13-disp 子集 171)——无判别力**：disp 与栈帧/局部变量普遍冲突（`4(%esp)` 型噪声淹没） |
| 环×table[0] shell 引用(0x100<len<0x3000) | **0 命中** |
| 环×头壳函数一/二阶可达 | **0 命中**——发现结构事实：s3 头 `call *0x4022a4`×11 全在**唯一 init 函数**(0x10A4E-0x10D15)体内，且该函数**无静态被引** = 块表驱动(dst 0xa244|bit0 调用)的**引擎 init 入口回调** |

## 2. 结构性结论（本楔真价值）
- **s3 入口 = 0x10A4E（init 函数）**，由块表条目 `+4c 55338→0x44 域`/`0xa244|bit0` 驱动调用——
  三段式启动定型：二段块表驱动 → s3 init（映射构造器+状态块）→ 交权 base+0xFA00。
- **主循环不在任何静态 Win32 引用环上**——s3 的每帧 Win32 调用走 **call *reg 动态面
  （37 处）+ GetProcAddress 解析缓存**（1999 VC++ 手工壳常态）。
  静态反汇编对它的覆盖到此为止：**判据穷尽三类，主循环归动态战役**。

## 3. s3 头壳 11 table[0] 引用全谱（复核）
0x10A6D/10A9B/10AC9/10AF2/10B1E/10B44 = VirtualAlloc 系 6；10B5F/10B76/10B8D/10BA4 = init 循环
内 4 槽分配；10CB6 = 0x9400 池分配——**s3 静态面零 DirectX/零消息 API**，DX 与消息
全靠运行期表填。

## 4. 楔9 定靶（二选一，默认①）
① **Wine 动态一帧**：Wine + demo-v1_4.EXE 真跑，winedbg 断 s3 init 返回处(base+0xFA00)
   与 37 个 call*reg 点，dump EIP 轨迹 → 主循环 VA 钉死（.analysis/ 有 Wine 取证先例，
   wine-pe-runtime-unpack 技能同型）；
② 37 call*reg 点静态聚类 + 名串引用（GetProcAddress 参串）人工推每点 API 身份。
主循环之后：A3 H_SVCLOW 槽对表 + `0x80083C58` 递减者(楔7-9 的 A3 遗留)在同一张
x86 服务表上闭环。

## 5. 否证落账
"回边+imm"、"大循环×disp"、"环×shell 引用/可达"三判据对 s3 主循环均无效——
记录为**静态方法边界**，防后续会话重烧。
