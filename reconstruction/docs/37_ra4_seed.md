# 37 — H-22 attempt1：halt 真身 0x1014 与 ra=4 毒源收网（task-050，2026-10-31）

## 1 本征新事实（推翻/精确化 §36 若干推断）
- **halt 不是 `pc=0`**：CHAIN 打印的 `final=00000000` 是"不可取指目标别名"假象。
  真实现场（EMITFAIL 日志修复后）：`EMITFAIL pc=00001014 op=42000010 ra=00000004 sp=801ffdd0`。
  `RAM 0x1014` 在金标真机 = 数据词 `0x42000010`（COP0 类，从未被真机执行），冷链向量页漫步
  `0x84,0x104,…,0x1000(→0x1014)` 本身**不是真机行为**——是 ra=4 毒后的坠落路径。
- **ra=4 全程不经过 pc=4 执行**（RACATCH 全链仅 1 次 0x4 转移 = halt 前最后一次）：
  → 第一颗毒 ra 由 **jalr/jal $0（寄存器值=0 的间接调用）** 直接 `mov_imm(4)+wrr31` 写入，
  再被帧保存者 `sw ra,sp,0x14` 落进 boot 栈。与 docs/35 `0x3610c jr t9(=0)` 锚一致。
- **JALZ 定址探针 = 0 命中**：毒源非定址 jal 0，必为间接 jalr（下一 attempt 的捕获面）。
- `H_JZSLED`（RAM 0x0 `v0=1;jr ra` ack 跳板 + 向量页定向 flush `jit_flush_range`）：
  跳板被执行（UNIQ 含 00000000）但**全链逐位不变**——jr $0 在 pre-sled 期已产生不可逆毒 ra，
  ack 语义救不回已污染的帧。与 task-043"单槽供给不足"同构。

## 2 机制（本征 commit）
- `H_JALZ`：JIT 发射期捕获 定址 jal→零区（含 from/delay/ra/v0/t9）。
- `H_JZSLED` + `jit_flush_range(lo,hi,n)`：ack 跳板 + 向量页三别名定向缓存失效。
- **EMITFAIL 日志修复**：原写 `devlog_fp()`（默认 NULL）致停机原因静默；现写 jit_rc_log
  并补 ra/sp/v0/t9 —— 这是 H 系列多次"final=00000000 谜团"的显示层根因。

## 4 attempt2 预备实验（同-session 追加，均零命中——重要排除项）
- `H_JALRZ`（jalr 链接寄存器直写钩，全 lreg、constructor 常开）：**0 命中** → ra=4 亦非 jalr→0 所种。
- 结合 §1 JALZ=0：**两种零跳转都不产生第一颗 ra=4**。剩余候选：`lw ra,槽`（内存残值）或
  向量区执行期语义。UNIQ 时序显示链**两次**进入向量页漫步（idx121 起 0,0x80,0x100…与 halt 前
  0x84..0x1014 二次），疑与 EXN 分发器（bfc1e988）扫描向量表/穿洞有关。
- attempt3 正题：反汇编 ROM 0x1E988 分发器本体 + `H_RAWATCH` 抓 `sw ra`/`lw ra` 全事件序列定种。

## 5 SESSION-56 attempt2：毒 ra=4 = 全链唯一事件，源头定样
- `H_RAWATCH` 修口（原亦 devlog 静默）+ 新增 `RAW31`（`lw $31,imm($rs)` 运行期现场：jpc/val/sp/si，
  门控 env，constructor 常开）。**干净运行（门控全关=基线）逐位不变**；开捕获后：
- **ra=4 全链仅发生一次**：441 个 ra 变化事件中唯一 `RAW pc=00000004 ra:800362c0->00000004`。
  前置链完整可溯：BIOS 启动码 `bfc01a60 → bfc03990(jal) → bfc06ed4`，
  `RAW31 jpc=bfc06ed4 val=00000004 sp=801ffed0 sim=+0x14`——**ra 从 boot 栈帧槽 lw 出 4**。
  该槽在真机由更深调用者（Sony C2 初始化契约的回调）写入合法返回地址；冷链中该调用者被
  H_C2HOME 自研契约替代 → 槽内留冷启动残值 4。**即 §4 的两个排除项的合取后果**：毒非零跳转
  所种，而是"自研契约改变调用深度 → boot 栈帧槽语义漂移"。
- Heisenbug 备案：开 RAW31 捕获会扰动停机点（提前至 pc=0x68，16 块）——emit 注钩改变块结构；
  结论以"门控关=基线 + 门控开=单次捕获"两跑互证。
- attempt3 锚：定样 `sp=801ffed0+0x14` 槽的**金标写入者**（真机同一 lw 链的更深层 `sw ra` 点），
  以最小自研补丁在该帧位预置合法哨兵返回地址（自有 handler，可续跑可观测），而非再赌全局机制。

## 6 SESSION-57 attempt3(3/3 终)：哨兵实验 + 金标对照——ra=4"毒"定性翻案
- Heisenbug 元凶修复：RAW31 钩 `mov_imm_eax(si)` 负位移编码 → 门控开时全链崩坏至 `pc=0x68`；
  改 `(uint32_t)(int32_t)si` 后**门控开=基线行为**（停机点回到 0x1014 逐位一致）。§5 的
  "单次毒事件@0x4" 系 heisenbug 路径伪象，**撤回**。
- `H_WATCH 1FFD80:1FFE40`（无扰动、走 H_JITDEV）定样写入者：唯一 176 写来自 `pc=bfc50000`
  （kernel 装载首块），`a=001ffdcc v=00000004`。
- **金标对照翻案**：`gold[0x1FFDCC]=0x00000004` —— 真机该槽**同样是 4**（另一槽 0x1FFDF8 金标=0，
  我链=4，小差异）。且金标同区含真返回地址 `bfc0df20/bfc0702c/bfc06998/bfc0e158/bfc067d8`——
  由更深层 BIOS 初始化调用（依赖完整 C2 回调契约）压栈。冷链被 H_C2HOME ack 截住那批调用，
  槽位停留在 boot 初始值；**4 不是"毒"，是"未完成的深层 init"的滞后残值**。
- `H_C2SENT`（帧槽哨兵+自研 handler@0x4C1B0）：安装成功、**基线停机逐位不变、哨兵零命中**——
  证明改写槽值不改变使用它的控制流。实验闭环。
- **终判（3/3 永久）**：不存在"单点修 ra=4"的通路。 halt 面（0x1014 数据词坠落）是深层 BIOS
  init↔C2 完整契约依赖的表观；与 docs/33 根判同环：需要的是**可运转的 C2 回调栈**（线程面
  task-048 §6 + 本任务 §6 互为表里），不是任何单槽/单词补丁。后继并入 H-21/H-22 联合面：
  task-049（中断/节拍流）与"自研 C2 契约完整化"必须同批设计。
