# 48 — M-6 金标态 handler 直跑探针：50 个 BIOS rootcall 的实证语义（task-062，SESSION-71）

## 1. 机制
`tools/hprobe.c`（`host/build/hprobe`）：加载 ROM + **GOLDEN_RAM 终态整幅**，按真 ABI
(`t1=cmd, t2=vec, ra=0xBFC4C1B0 哨兵, sp=boot 栈顶`) 逐个直跑三族表指向的 handler；
停机时经 `jit_lib_serve()` 放行嵌套 syscall/rootcall 续跑（上限 50 次）。
清单 = docs/46 普查的 50 桩→表槽值（**相对偏移语义**，<0x80000 → `0xBFC00000+off`）。

## 2. 结果总览（复算锚）
`HPSUM total=50 break=27 halt=23` — **27 个 handler 真执行且经哨兵干净返回**（首见 BREAK
blocks=2..4 即返 = 叶函数），23 个停于嵌套派发/serve 上限（深服务，非故障）。
这直接补验了 docs/47 的 36 个未锚 cmd：**它们全部是可运行的真 BIOS 服务**，
"深 cmd 需要 H-25 才能实现"的假设在 BIOS 侧不存在——缺口纯在引擎侧调用方。

## 4. 终判与 H-25 影响
- BIOS 服务面**运行时活性已证**：27/50 直接 BREAK，23/50 需深 serve 环境——两者都不是"缺失"。
- H-25 引擎兼容层的对接面由此收敛为**纯转发生成器**：按 docs/41 ABI 打包参数 →
  `pc=0xBFC00000+表[vec基+cmd*4]` → 哨兵收 v0。可在 host 侧以本探针骨架直接孵化。
- 停机的 23 个记录 serve 上限行为：其中 serve=51 群(0xB0/0x15.. 等)为嵌套 rootcall 族,
  实施 H-25 时提升 serve 预算+递归表可全通。
